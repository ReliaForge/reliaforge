# 安全模型

ReliaForge 默认允许匿名读取平台状态，但对所有插件业务路由、WebSocket 会话与生命周期操作强制要求身份验证。

## 只读接口

存活检查、就绪检查、平台状态、插件列表和插件详情仅读取当前内存状态，不会修改插件状态，也不会返回实际配置值。配置说明接口只展示字段名与类型，自动省略敏感字段值及敏感默认值。

## 受保护的操作与 WebSocket

插件 HTTP 接口、SSE 日志流、WebSocket 连接升级（如容器终端或 LXC 终端）以及插件启动、停止、重启请求均经过后端统一认证。浏览器发起的变更请求与 WebSocket 握手还会根据同源策略或 `RELIAFORGE_TRUSTED_ORIGINS` 校验 `Origin` 与 `Sec-Fetch-Site` 请求头。

`available_actions` 仅用于提示控制台当前状态支持哪些操作，后端会对每次请求重新校验操作者身份与运行状态。

## 本地开发

仅当处于开发或测试模式且后端绑定在回环地址（`127.0.0.1` 或 `::1`）时，才允许免认证管理操作。跨源本地调试时需配置精确到协议、主机和端口的 CORS 允许来源。开发模式仅限可信个人工作站使用。

## 生产代理认证

生产环境必须满足以下条件：

- 限定地址段范围的可信反向代理网络；
- 仅接受来自可信代理对端注入的操作者身份请求头；
- 在每次 HTTP 与 WebSocket 转发请求上校验高强度代理共享密钥；
- 保留反向代理真实直接 TCP 对端地址的网络拓扑。

上述配置不完整时，后端会直接拒绝启动；生产模式下同时自动关闭交互式 OpenAPI 文档。

## 浏览器与插件信任边界

前端构建产物不保存任何管理密钥。Proxmox、Kubernetes、Argo CD 等上游凭据必须保存在后端环境变量或挂载凭据文件中，切勿写入公开暴露给浏览器的 `VITE_*` 变量。

插件作为受信任的 Python 与前端代码在部署环境内运行。启用第三方插件前请先完成代码审阅；ReliaForge 不对不可信插件提供沙箱隔离。

[在线演示](https://demo.reliaforge.dev/?lang=zh)不包含后端，也不会发起管理请求。发现疑似安全漏洞时，请按仓库内的 `SECURITY.md` 私下报告。
